# MILG 엔진 보강 (11-09)

같은 검증 방식(공구 · 설비 · 그룹을 통째로 빼고 학습 → 그것으로 평가). 공구 누적 사용량 제외. 부스팅은 비교 기준으로만 쓰고 엔진에는 넣지 않음.
재현: `python -m mlng_ai benchmark <MCT 요약 폴더>` (MCT) · `python -m mlng_ai mct-pressfit <MCT 요약 폴더> <압입 요약 폴더>` («엔진 보강» 칸).
저장: `state/base/mct_engine_{hmotp,nasa,stiehl}.json` — 엔진 상태 + 공정 전용 입력 표준화 값 (JSON 하나, 외부 모델 파일 없음).

## 보강 내용 (고정 규칙 — 데이터마다 고르지 않음)

1. 공정 전용 입력: 그 공정의 원본 숫자 칼럼 + 공구 교체 후 처음 10회 대비 변화를 학습 묶음 기준으로 표준화해 엔진 슬롯 «L:칼럼» 으로 더함. 절반 넘게 비어 있는 칼럼(설비마다 다른 채널)은 뺌.
2. 곡선 공정(압입 계열): 곡선 5구간 평균 · 기울기 · 평균 높이 + 양쪽 벗어남(|z| · z²) — «너무 크거나 작으면 불량».
3. 실행 설정: 공정별 사전 폭 δ 1.0 · 한 번에 학습 · 망각 없음 · 반복 50 (설정만 바꾸면 효과 없음 — 1과 함께만 의미).
4. 새 설비 · 새 공장: 공정 전용 입력은 절대 수준이 달라 0.72로 나빠짐 → «교체 후 변화» 슬롯만 사용(0.88).

## 버그 수정
- 결과 칼럼 설명 «조립 불량 (OK 아님)» 의 «OK» 때문에 엔진이 압입 정답을 뒤집어 학습하던 것 → «아님 · 불량 · NG · 불합격» 이 함께 있으면 뒤집지 않음.

## 채택하지 않은 것
| 항목 | 결과 |
|---|---|
| 꺾은선 확장 (상위 10개 × 3구간) | 공정 전용 입력보다 낮음 (0.95~0.96) · 상위 5개 교체 후 변화만 꺾으면 Stiehl 0.96 이지만 HMoTP 0.04 로 뒤집힘 — 불안정 |
| 곱셈 항 (상위 5개 쌍) | HMoTP 0.64 — 과적합 |

## 임계값
| 방식 | 오경보 | 놓친 공구 |
|---|---|---|
| 학습 데이터 안 (정상 행 5%) | 9~22% — 목표 초과 | 적음 |
| 안쪽 교차검증 | HMoTP 0.7% · NASA 6% · 이전 7% — 목표 근접 | 늘어남 (HMoTP 0/3 → 2/3, NASA 4/15 → 8/15) |
→ 오경보 목표는 고객과 정하고 안쪽 교차검증으로 맞춘다.
