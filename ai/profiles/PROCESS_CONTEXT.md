# 공정 인식과 템플릿 연결

`process_context.py`는 입력 칼럼과 단계 구조를 확인하는 보수적 규칙 기반 인식기입니다. 학습된 공정 분류기나 확률 출력은 아닙니다. 현재 지원하는 입력은 정해진 이름을 사용하는 밀링 원시 구간, HMoTP 계열 요약, 체결 단계 JSON, CausalMan 압입 스키마입니다. 처음 보는 공급사 칼럼의 일반적인 이름 매핑은 기존 schema 모듈의 별도 기능입니다.

1. 공정 특유의 신호 조합 확인. 힘·토크 단독 칼럼으로 확정하지 않음.
2. 사용자가 지정한 공정과 대조. 충돌·복수 후보·미확인은 확인 필요 반환.
3. 해당 공정의 MCT/체결 템플릿 제안. 모델과 입력 계약에 맞는 추론 경로가 명확할 때만 모델 선택.
4. 원시 곡선과 식별자·조건이 있으면 RMS/최댓값/기울기/면적/확인된 정상 기준 대비 변화 계산. 누락 시 항목별 판단 제한 표시.
5. 계산만 가능한 경우 `template_analysis_only`와 `quality_prediction: null` 반환. 새 템플릿 계산을 학습하지 않은 기존 가중치에 자동으로 주입하지 않음.

## 호출

```python
from mlng_ai.service import Service
service = Service('state')
result = service.analyze_process(df, process='mct')
result = service.predict('auto', df)
```

`POST /ai/v1/analyze-process`는 `{process, rows, template_id}`를 받습니다. `process`와 `template_id`는 생략 가능합니다. 기존 테넌트 인증·처리량 제한을 공유합니다. `/ai/v1/predict`에서도 `process: auto` 또는 명시적 `template_id`를 지원합니다. 합성 모델은 입력이 비슷하더라도 자동 선택하지 않습니다. MCT 기본 모델이 여러 개면 하나를 임의 선택하지 않습니다.

```powershell
cd "C:\Users\dksgu\Desktop\code\mlng-mes\mlng-mes\ai"
python -m mlng_ai.process_context "작업목록.json" --process screw --out "분석결과.json"
```

JSON은 작업 객체 배열입니다. 체결 작업 구조는 `README.md`의 공정 템플릿 입력 계약을 따릅니다. CSV 요약은 공정 후보를 제안할 수 있지만 원시 곡선이 없으면 곡선 계산이 가능하다고 표시하지 않습니다.

분석은 읽기 전용이며 요청 안에서만 작업 이력을 순서대로 재생합니다. 고객별 기준·공구 상태를 지속 저장하는 수집 경로는 `ProfileRuntime.save/load`를 명시적으로 사용해야 합니다. 입력 행은 시간순이어야 하며 `confirmed_normal`은 운영 시점에 확인한 정보여야 합니다. 브라우저/MES의 수집 필드와 공정 코드 매핑 UI, 기업별 템플릿 상속 편집기는 이번 범위에 포함되지 않습니다.

## 정확도 이외의 이점과 검증 범위

- 잘못된 공정·합성 모델로 연결하는 오류 방지: 충돌/모호성/합성 자동 선택 금지 테스트로 동작 확인.
- 데이터 연동 계약 명확화: 부족한 신호·공구/교체 회차 ID·조건을 구체적으로 안내. 고객 연동 시간 절감 폭은 현장 측정 전.
- 설명·재현: 선택 근거, 템플릿 ID·버전·해시, 계산값과 판단 제한 반환. 동등한 재현에는 원본 입력과 모델·정규화 설정도 보관해야 함.
- 공정 지식 재사용: 동일 계산을 신규 고객 기준과 분리해 유지 가능. 다른 재질/공구 조건에 임계값까지 그대로 재사용하면 안 됨.
- 운영 통제: 읽기 전용 검토와 학습/승격 구분. 현장 설정 오류는 그대로 계산에 전파될 수 있으므로 승인·버전 관리 필요.

앞서 실시한 품질 모델 특징 비교에서 체결은 개선, MCT는 악화됐습니다. 이번 공정 인식 기능의 품질 예측 정확도 개선이나 전체 고객의 인식률을 측정한 결과는 아닙니다. 새 공정 특징은 재학습·공정별 검증 후에만 운영 가중치에 반영합니다.
